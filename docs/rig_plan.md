## 1. なぜ試験装置か

ソフトは「画像 → ストローク → 工程 → G-code → Klipper マクロ込みの安全チェック → カメラで見ながら描く」まで
シミュレーションで一通り動いている。一方、**シミュレータの筆の物理はすべて推測値**:

- 押し込み量 → 線幅の関係（今は `width * (0.35 + 0.65 * pressure)` の仮定）
- 1回のディップで描ける長さ（`capacity`）
- 何回洗えば次の色が濁らないか（洗浄回数）
- キャンバスのたわみ・凹凸（張りキャンバスは1〜2mm沈む）

ここが違うと絵の出来・時間見積もりが全部崩れるので、本体を作る前に**手持ちの3Dプリンタに筆を1本付けて実測する**。

その他シミュレーション未確認: Klipper の加減速（時間と速度プロファイルの実現性）、立体的な干渉、洗浄の実効性、
油絵の具のツヤのカメラ写り、Klipper への層ごと送信（未実装）。

## 2. 最終的な実機のおすすめ形（参考）

→ **CAD を作成済み**: `machine/`（`machine/cad/machine.py`、STL 26 種・組立 GLB・部品表・天板の切り出し図、チェック 71 項目）。CAD のチェックで配置の問題が見つかり、`configs/machine_final.yaml` のラック・布・カメラ待機位置と、マクロのラック出し入れ距離（`rack_slide` 35mm）を変えた（詳細は `machine/README.md`）。

キャンバスとステーションは固定、ガントリーが上を動く**平台プロッタ型**（作業範囲 約 700×450mm）。

- フレーム: アルミフレーム 2020/2040 + 3Dプリント部品
- XY: ベッド固定・ガントリー移動（CoreXY かデカルト、ベルト）。濡れた絵の具・油壺を揺らさない
- Z: 送りねじ + **ばね付きスライド**（位置でなくばねの縮みで筆圧を決め、凹凸を吸収）
- キャンバス高さ: タッチプローブ + Klipper `bed_mesh` で凹凸を補正
- 回転A: モーターはヘッド側に固定し、ベルトで筆ホルダーだけ回す → 回転側に配線なし → **回転制限なし**
- ツールチェンジ: 樹脂の筆ホルダー + 磁石 + キネマティック位置決め、ラックで着脱
- 洗浄: **壺2つ**（粗洗い・仕上げ）、底に金属メッシュ、縁にしごき板
- パレット: 取り外せる陶器/ガラス皿（12穴）
- キャンバス: 試作はキャンバスボード
- カメラ: 真上固定、拡散照明 + **偏光フィルター2枚（直交偏光）**で油のツヤを消す
- 制御: 3Dプリンタ用基板（BTT Octopus 等）+ Raspberry Pi（Klipper / Moonraker / カメラ）

## 3. 試験装置の機構

手持ちの3Dプリンタ（**機種は未確認 — 最初に決める**）のキャリッジ前面に取り付ける。ヒーターは一切使わない。
v1 は**回転軸なし**（平筆は固定向きで、X方向・Y方向の線を両方描いて幅広・幅狭を測る）。

### 3.1 筆ホルダー（ばね付きスライド）
```
  [取付板]  キャリッジ前面にM3で固定。横長スロット2本（穴間隔 20〜45mm 可変）で機種差を吸収
     │
  [ガイド] 上下の耳に Ø4 シャフト2本（間隔 ~24mm）を固定
     │
  [スライダー] LM4UU ×2 圧入、中央に筆の縦穴（割りクランプ + M3）
     │          ← 筆が当たるとスライダーが上へ逃げる（ストローク ~12mm）
  [ばね] 筆の柄の周りに同軸で配置（外径10・内径8〜9・自由長20〜25・線径0.5〜0.7mm 目安）
     │
  [オプション] マイクロスイッチ取付座: スライダーが ~1mm 上がると ON → Klipper の probe としてキャンバス面検出
```
- 筆の柄は **~100mm に切る**（長いとプリンタ上部フレームに当たる）
- 筆先はノズルより **45mm 以上下**に出す（洗浄壺の縁にノズルが当たらないように）
- 柄の径は部品のパラメータ（既定 Ø6.5、クリアランス 0.3）

### 3.2 ベッド上の配置（220×220 ベッド想定、設定で変更可）
```
┌──────────── ベッド ────────────┐
│ ┌ ボード枠 190×150 ───────────┐ │   四隅に ArUco マーカー(20mm, ID 0-3)の窪み
│ │ ▣                       ▣ │ │   中にキャンバス紙 + 裏板（描画範囲 ~150×110）
│ │      描画エリア             │ │
│ │ ▣                       ▣ │ │
│ └────────────────────────────┘ │
│ [ステーショントレイ 190×60] 枠の前辺に差し込み固定  │
│   ◯色A  ◯色B   ◎洗浄皿(Ø50, 高さ30以下)   ▭拭き取り布 │
└────────────────────────────────┘
```
- トレイは枠に固定 → 位置は設計値で決まる。**実測はジョグで1点（マーカー0の中心にノズル座標を合わせる）だけ**
- Z は3点をジョグで実測して設定に書く: キャンバス接触Z、絵の具皿の接触Z、洗浄皿の底Z

### 3.3 部品表（目安）
Ø4×60mm シャフト×2、LM4UU×2、圧縮ばね（上記）、M3 ねじ・ナット少々、マイクロスイッチ（任意）、
キャンバス紙 or 薄いキャンバスボード、小さい陶器皿×2、低いガラス皿（洗浄用）、布、ArUco マーカー印刷（普通紙 → 窪みに貼る）。
印刷部品: 取付板+ガイド、スライダー、ボード枠、ステーショントレイ（PETG 推奨、溶剤に PLA より強い）。

### 3.4 取り扱いの注意
- **ホーミングは筆を付ける前に**行う（Z ホーミングで筆がベッドに刺さるため）。筆を付けたらモーターの電源を切らない
  （Klipper は `idle_timeout` を長くする）
- G-code は XY のみ / ホーミングなしで始める

## 4. 試し描きシート（G-code 生成）

1シート = 1枚のキャンバス紙。G-code は G0/G1 のみ（円も折れ線で）で **Klipper / Marlin 両対応**、
一時停止は Klipper `PAUSE` / Marlin `M0` を切替。各シートと一緒に、線の位置・条件を書いた `sheet.json` を出す（解析で使う）。

| シート | 内容 | 求めるもの |
| --- | --- | --- |
| `width` | 押し込み量 0.5〜最大を数段階、各 60mm の直線を X 方向・Y 方向に | 押し込み量 → 線幅のカーブ、入り/抜きの形 |
| `capacity` | 1回ディップして全押しのジグザグ（推定容量の 1.5 倍の長さ）| 描ける長さ。濃さが初期の半分になる長さ L½ から `capacity = L½ / 0.77`（レンダラのモデルに合わせた換算）|
| `wash` | 色Aで汚す → 洗浄 n 回（0,1,2,4,8）→ 拭き → 色B の線。最初にきれいな筆で色Bの基準線 | 色Bの基準線との ΔE が 3 未満になる最小洗浄回数 |
| `strokes` | `human_motion` で作った実際のストローク（直線・S字・入り抜き） | 実物とシミュレータの描画の重なり（IoU・幅の差）= モデルの忠実度。ピッチ用の「実物 vs シミュレーション」比較にも |
| `speed`（任意）| 同じ押し込みで速度違いの線 | 速度による幅・かすれの違い |

## 5. 写真の解析

1. 写真（スマホでも可、真上から・ツヤが写らないように）から ArUco 4個を検出
2. ホモグラフィで枠の mm 座標に正規化（10 px/mm）
3. 背景（キャンバス）の色を線の間から推定し、ΔE で塗れた所を判定
4. 各線の中央 60% で幅を平均（入り/抜きは別に幅の推移をグラフ化）
5. 出力: `rig_results.json`、グラフ画像、`machine.yaml` に貼れる筆設定。`--apply` で直接書き込み

## 6. ソフト側の変更予定

- `configs/rig.yaml` + `painter/rig/config.py`: ベッド寸法、枠の基準点（ジョグ実測値）、Z 3点、テストする筆、押し込み量リスト、ファームウェア種別
- `painter/rig/sheets.py`: 各シートの動作列 + メタデータ
- `painter/rig/gcode.py`: G-code 出力（Klipper/Marlin）、上面プレビュー画像
- `painter/rig/markers.py`: 印刷用 ArUco マーカー画像（300dpi・実寸）
- `painter/rig/analyze.py`: 写真解析 → 結果・グラフ・設定案
- `painter/rig/simulate.py`: シートを既知の「真の筆」で描いた疑似写真（斜め・照明ムラ・マーカー付き）を作る
  → 解析で真の値が戻るかを確認（実機前に解析を検証する。洗浄の検証用に残留色モデル: 残り = 0.5×0.55^n を疑似写真側だけに入れる）
- `painter/config.py` の `Brush` に `width_curve: [[押し込みmm, 幅mm], ...]`（任意）を追加し、レンダラは
  あればそれを使う（なければ今の式）
- CLI: `painter rig markers | gcode SHEET | simulate SHEET | analyze PHOTO --sheet sheet.json [--apply]`
- テスト: 疑似写真 → 解析で、線幅カーブ・容量・洗浄回数が許容誤差内で戻ること。G-code の Z がキャンバス上で最大押し込みを超えないこと
- 3D部品: **作成済み** → `rig/cad/rig.py`（OpenSCAD ではなく Python + manifold3d。STL・プレビュー・寸法チェック 30 項目）+ `rig/README.md`（部品表・印刷設定・組立・測定手順）。
  以下は当初の案:
  OpenSCAD はこのPCに未導入で、検証のための一時ダウンロードは見送り。**別PCで OpenSCAD を入れて STL 出力・形状確認**する
